# 教师多维度评价系统 — 产品方案

> 面向北京某国际学校 | 版本 V2.0 | 2026-06-10
> 基于 SuperPower 模式：@产品经理 + @项目经理 + @算法工程师

## 一、对标研究：成熟评价框架与产品

方案设计不是从零想象，而是基于以下经过大规模实践验证的框架和产品。

### 1.1 Danielson Framework for Teaching (FFT)

Charlotte Danielson 1996 年提出，**美国最广泛使用的教师评价框架**，被超过 1000 个学区采用。2022 年精简为 FFT "Intellectual Engagement" 版。

| Domain (域) | 核心关注 | 组件数 |
|:---|:---|:---:|
| **1. Planning and Preparation**（计划与准备） | 教学内容知识、教学设计、评估设计 | 6 |
| **2. Learning Environments**（学习环境） | 尊重与融洽氛围、学习文化、课堂流程管理、学生行为管理 | 5 |
| **3. Learning Experiences**（学习体验） | 师生沟通质量、提问与讨论技巧、学生参与、评估运用、灵活响应 | 5 |
| **4. Principled Teaching**（原则性教学） | 教学反思、记录保持、家校沟通、专业共同体参与、专业成长、职业操守 | 6 |
| **合计** | | **22** |

**评分方式**：每个组件用 4 级量规（Unsatisfactory / Basic / Proficient / Distinguished），每级有具体行为描述。

> 来源：ASCD 出版《Enhancing Professional Practice: A Framework for Teaching》(Danielson, 2007, 2nd ed.)；2022 精简版参考 danielsongroup.org

### 1.2 Marzano Focused Teacher Evaluation Model

Robert Marzano 基于 5000+ 教学研究论文提炼的实证模型。

| Domain | 关键要素数 | 说明 |
|:---|:---:|:---|
| **Standards-Based Planning**（基于标准的计划） | 8 | 明确学习目标、分尺度、衔接前测 |
| **Standards-Based Instruction**（基于标准的教学） | 10 | 直接教学、练习与加深、知识应用、策略运用 |
| **Conditions for Learning**（学习条件） | 5 | 建立规则流程、组织物理空间、建立师生关系 |
| **Professional Responsibilities**（专业职责） | 2 | 坚持学校规范、促进同事协作 |

**评分方式**：5 级量表（Not Using / Beginning / Developing / Applying / Innovating），共 23 个核心要素，强调可观测的行为证据。

> 来源：Marzano Resources，《The Marzano Focused Teacher Evaluation Model》(2017)

### 1.3 CLASS (Classroom Assessment Scoring System)

Pianta, La Paro & Hamre 开发，**专注于课堂师生互动质量**，被 Head Start 等联邦项目强制使用。

| Domain | Dimensions（维度） | 说明 |
|:---|:---|:---|
| **Emotional Support**（情感支持） | Positive Climate, Teacher Sensitivity, Regard for Student Perspectives | 课堂气氛、教师敏感度、尊重学生视角 |
| **Classroom Organization**（课堂组织） | Behavior Management, Productivity, Instructional Learning Formats | 行为管理、效率、教学形式多样性 |
| **Instructional Support**（教学支持） | Concept Development, Quality of Feedback, Language Modeling | 概念发展、反馈质量、语言示范 |

**评分方式**：经认证的观察员用 7 级量表打分，需完成 4 个观察周期。

> 来源：Pianta, R. C., La Paro, K. M., & Hamre, B. K. (2008). *Classroom Assessment Scoring System™: Manual K-3.*

### 1.4 TAP System (Teacher Advancement Program)

NIET (National Institute for Excellence in Teaching) 开发的综合性教师评价与激励系统。

**三大部分**：多维度评价 + 职业发展路径 + 绩效薪酬。评价维度分为 **教学实践**（Instruction）、**设计规划**（Designing & Planning）、**学习环境**（Learning Environment），每个维度有 5-10 条量规指标。

> 来源：NIET,《TAP Evaluation and Compensation Guide》

### 1.5 国内落地产品

| 产品 | 核心评价维度 | 特色 |
|:---|:---|:---|
| **科大讯飞 智慧教师评价** | 课堂行为分析（师生互动频率/提问类型/学生参与度）、教学能力、信息化素养、学情诊断准确性 | AI 录播分析（语音+视觉），2000+ 学校落地 |
| **腾讯教育 智慧校园** | 学生评教、家长反馈、同行评议、教研员评价 | 多角色评价 + 企业微信/教务系统深度对接 |
| **好未来/学而思 T 级评级** | 教学能力分层（T1-T5），结合学生留存率、满意度、AI 模拟课堂实战 | 重结果导向 + AI 模拟实战评估 |
| **ClassIn 教学分析** | 教师行为分析（基于课程回放）、作业批改质量、课堂互动频次 | 专注在线教学场景 |

### 1.6 框架对比 — 哪些对我们有用

| 框架 | 对标价值 | 可直接借鉴的维度 |
|:---|:---|:---|
| **Danielson FFT** | ⭐⭐⭐⭐⭐ 最通用 | 四个 Domain 结构直接可用作方案骨架 |
| **Marzano** | ⭐⭐⭐ 侧重实证 | 学生成绩增值(VAM)的统计方法论 |
| **CLASS** | ⭐⭐⭐⭐ 互动质量 | 师生互动的量化指标设计 |
| **TAP** | ⭐⭐⭐ 制度设计 | 评价 + 发展 + 激励的闭环设计 |
| **科大讯飞** | ⭐⭐⭐ 技术实现 | AI 课堂分析的本地化实践 |

## 二、方案定位与交付范围

### 2.1 核心原则

1. **不做视频/音频 AI 分析**（1 个月做不完，推入 2 期）
2. **对接现有系统数据**（学校已有 LMS/教务/问卷数据，直接吃进来）
3. **评价框架对标 Danielson FFT**（4 大域 22 组件），适当简化
4. **支持多数据源加权评分**（课堂观察、学生成绩、家长反馈、同行互评）
5. **输出结构化的评价报告和看板**（雷达图、排名、趋势）

### 2.2 Phase 1 vs Phase 2

| | Phase 1（本次交付） | Phase 2（远期规划） |
|:---|:---|:---|
| **工期** | 1-2 工程师 × **1 个月** | 待定 |
| **数据来源** | LMS 成绩、教务考勤、学生/家长问卷、同行评分表 | 课堂录播 AI 分析（语音/视频） |
| **评价方式** | 多数据源手动/批量导入 → 加权计算 | AI 自动提取课堂行为指标 |
| **核心产出** | 评价配置 + 数据录入 + 评分计算 + 看板报告 | AI 课堂分析引擎 + 增值模型 |

## 三、产品设计

### 3.1 评价框架（对标 Danielson FFT）

采用 FFT 四大域结构，结合国际学校场景做调整：

#### Domain 1: 教学设计 (Planning & Preparation) — 权重 15%

| 组件 | 数据来源 | 评分方式 |
|:---|:---|:---|
| 1a. 教学内容知识掌握 | 教案提交系统 / 教研组长评价 | 手动评分 1-4 |
| 1b. 教学目标清晰度 | 教案系统 / 同行听课表 | 手动评分 1-4 |
| 1c. 教学资源选择 | 教研组长评价 | 手动评分 1-4 |
| 1d. 评估设计 | 作业数据（LMS 导出） | 自动计算 + 手动确认 |

#### Domain 2: 学习环境 (Learning Environments) — 权重 20%

| 组件 | 数据来源 | 评分方式 |
|:---|:---|:---|
| 2a. 师生关系与课堂氛围 | 学生问卷（匿名，每学期） | 自动计算均分 |
| 2b. 学习文化建设 | 学生问卷 + 班主任互评 | 自动计算均分 |
| 2c. 课堂流程管理 | 同行听课表 | 手动评分 1-4 |
| 2d. 学生行为引导 | 教务系统违纪/表扬记录 | 自动计算比率 |

#### Domain 3: 教学实施 (Learning Experiences) — 权重 35%

| 组件 | 数据来源 | 评分方式 |
|:---|:---|:---|
| 3a. 师生互动质量 | 学生问卷 + 同行听课 | 综合计算 |
| 3b. 提问与讨论技巧 | 教研组长听课评价 | 手动评分 1-4 |
| 3c. 学生参与与投入 | 学生问卷 | 自动计算 |
| 3d. 评估与反馈运用 | LMS 作业批改及时性/质量 | 自动提取 + 手动抽查 |
| 3e. 灵活性与差异教学 | 同行互评 + 教研组长评价 | 手动评分 1-4 |

#### Domain 4: 专业素养 (Professional Responsibilities) — 权重 30%

| 组件 | 数据来源 | 评分方式 |
|:---|:---|:---|
| 4a. 教学反思与改进 | 教师自评表 | 教师自评 1-4 |
| 4b. 家校沟通质量 | 家长满意度问卷 | 自动计算 + 沟通频次统计 |
| 4c. 专业发展参与 | 培训/教研签到系统 | 自动统计 |
| 4d. 同事协作 | 同事互评问卷 | 自动计算均分 |
| 4e. 学生成绩增值 | LMS 标准化考试成绩 | Value-Added 计算 |

### 3.2 评分量规（对标 Danielson 四级量规）

| 等级 | 分数 | 含义 | 关键特征 |
|:---|:---:|:---|:---|
| **Unsatisfactory**（不合格） | 1 | 未达基本标准 | 教学活动缺乏结构；学生常游离；沟通少 |
| **Basic**（基本达标） | 2 | 部分达标但待改进 | 教学活动进行但不深入；部分学生参与 |
| **Proficient**（熟练） | 3 | 专业水平 | 教学活动高效，学生积极参与，有明确学习成果 |
| **Distinguished**（卓越） | 4 | 示范水平 | 学生高度自主，实践创新，成为校内示范 |

> 来源：该量规直接来自 Danielson FFT 的官方 4 级评分标准

### 3.3 产品功能模块

只做 Phase 1 能交付的部分：

| 模块 | 功能 | 工时占比 |
|:---|:---|:---:|
| **评价配置中心** | 维度/组件配置、权重调整、评分量规定义、学期模板 | 15% |
| **数据接入层** | LMS 成绩导入、教务考勤导入、问卷数据导入（CSV/Excel）、手动评分表单 | 25% |
| **评价计算引擎** | 多源加权聚合、归一化、排名计算 | 15% |
| **教师发展看板** | 个人雷达图、历史对比、维度排名、改进建议生成 | 20% |
| **校长总览看板** | 全校分布热力图、高潜力/需关注教师列表、学科均衡分析 | 15% |
| **报告生成** | 教师个人评价报告 PDF 导出 | 10% |

### 3.4 用户角色

| 角色 | 看什么 | 做什么 |
|:---|:---|:---|
| **校长** | 全校总览、高潜力/需关注教师、学科均衡 | 审批评价周期、查看 AI 建议 |
| **教研组长** | 组员雷达图对比、薄弱维度 | 填写听课评价、审核自评 |
| **教师本人** | 个人雷达图、历史对比、改进建议 | 查看反馈、填写自评、上传材料 |
| **家长/学生** | 填问卷界面（仅评价参与者） | 填写学期末满意度问卷 |

## 四、实施计划（Phase 1 — 1-2 人 × 1 个月）

### 4.1 交付日历

按 4 周 × 1.5 工程师（1 全栈 + 0.5 数据/后端）= **30 人·天** 排期：

| 周 | 任务 | 交付物 | 工时 |
|:---|:---|:---|:---:|
| **W1** | 技术选型 + 数据库设计 + 评价配置模块 | DB Schema + 评价配置 CRUD | 5 天 |
| **W2** | 数据导入 + 评分计算引擎 | CSV 导入 + 多源加权评分 API | 7 天 |
| **W3** | 教师看板 + 校长总览 + 报告生成 | 雷达图/热力图/PDF 导出 | 8 天 |
| **W4** | 联调测试 + 试点部署 + 文档 | 完整可演示系统 | 5 天 |
| **缓冲** | Bug 修复 + 调整 | | 5 天 |

### 4.2 里程碑

| 里程碑 | 时间 | 验收标准 |
|:---|:---|:---|
| **M1: 评价配置可用** | W1 末 | 校长能创建学期计划，设置维度权重 |
| **M2: 数据流贯通** | W2 末 | 导入 LMS 成绩 + 问卷数据 → 评分引擎正确计算 |
| **M3: 看板可演示** | W3 末 | 校长/教师看板可用，雷达图数据正确 |
| **M4: 上线交付** | W4 末 | 完成试点部署 + 用户手册 |

### 4.3 技术栈

| 层 | 选型 | 理由 |
|:---|:---|:---|
| **前端** | Vue 3 + ECharts/TDesign | 与客户现有技术栈一致，快速出图 |
| **后端** | Python Flask/FastAPI | 数据处理能力强，1 人可同时写前后端 |
| **数据库** | PostgreSQL | 结构化评价数据，JSONB 存灵活配置 |
| **部署** | Docker Compose | 学校内网单机部署 |

### 4.4 Phase 2 规划（不做本次）

| 模块 | 说明 | 依赖 |
|:---|:---|:---|
| **课堂 AI 分析** | 语音转文字 → Bloom 提问层次识别 → 师生话轮比 | 需要录播系统 API 对接 |
| **视频行为分析** | 学生参与度热力图、教师站位轨迹 | 需要摄像头部署 + AI 模型 |
| **增值模型(VAM)** | Student Growth Percentile 精确计算 | 需要至少 2 学期成绩 baseline |
| **家长端小程序** | 微信小程序问卷 + 报告查看 | 需微信认证 + 开发 |
| **AI 自动评语** | 数据 → LLM 生成评价报告 | 数据积累后效果好 |

## 五、风险与应对

| 风险 | 等级 | 应对 |
|:---|:---:|:---|
| 学校各系统数据格式不一致 | 高 | W1 先做数据摸底，写数据字典；导入层做灵活映射 |
| 教师对评价系统抵触 | 中 | Phase 1 先以"教师发展工具"而非"绩效考核工具"定位；个人报告仅教师本人和教研组长可见 |
| 1 个月时间不够 | 中 | 严格剪裁：不做 AI 分析、不做移动端、不做审批流（先手动）；缓冲 5 天已预留 |
| 客户需求变化 | 低 | 每周 demo 一次，早发现早调整 |

## 六、DIKW 层次总结

```
Data（数据）     →  LMS 成绩 + 问卷结果 + 考勤 + 手动评分
Information（信息）→  各维度分项得分 + 排名 + 趋势
Knowledge（知识）  →  雷达图 + 教师强弱项分析 + 学科对比
Wisdom（智慧）    →  校长决策（培训资源分配/教师发展计划）
```

Phase 1 做到 Knowledge 层，Phase 2 通过 AI 分析迈向 Wisdom 层。
