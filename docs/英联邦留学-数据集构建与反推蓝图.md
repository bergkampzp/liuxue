## 〇、扣住的真实资产 + 一个必须先补的缺口

**已确认的真实表结构** `raw.liuxue_admissions`（一亩三分地/寄托案例，英联邦反推核心资产）：
`school, program, degree, season, year, decision, gpa, gre, gre_v, gre_aw, toefl, ielts, undergrad_school, undergrad_major, comment, source_url, source, crawled_at`

- ✅ 黄金字段：`undergrad_school`（本科院校）、`undergrad_major`（本科专业）、`ielts`（雅思总分）、`decision`
- ❌ 缺口：无 `country`；`ielts` 只有总分无小分(L/R/W/S)；`decision` 无 Conditional/Unconditional；`gpa` 百分制/4.0 制混填

> **⚠️ 实施第一坑**：当前 `dbt_liuxue/models/staging/_sources.yml` **只声明了 `gradcafe_admissions`，没登记 `raw.liuxue_admissions`**——而它才是英联邦的核心源。第一步必须补登。

**架构决策**：新建独立的英联邦支线 `models/uk/`，**全程不触碰**现有美研模型（`int_admissions_cleaned / feat_gpa_threshold / feat_gre_impact / mart_school_admission_stats`，保留服务美研/对照）。英联邦录取轴是 `(英国校 × 专业大类 × 中国院校档 × 均分 × 雅思小分)`，与美研的 `school+degree` 完全不同，改造会污染已上线 mart。唯一复用：`raw.liuxue_admissions` 源 + "低分位定阈值"统计思路。`feat_gre_impact` 对英联邦失效，不进任何英联邦功能。

## 一、全局前置：三张维表 + 一条清洗主干（所有功能共享地基）

### 维表 1 `dim_cn_university`（中国院校主数据）— 【采集 + LLM 补别名】
**所有反推的第一前置**——英国校真实分档依据中国本科档位。
- 字段：`cn_uni_id PK, name_zh, name_en, aliases[], is_985, is_211, is_double_first_class, ruanke_rank, qs_rank, tier_label`
- `tier_label` 枚举：`985 / 211 / 双一流 / 双非一本 / 双非二本 / 海本 / 其他`
- 来源：GitHub 现成中国院校 985/211/双一流标签数据集 + 软科/QS 排名爬取
- **`aliases[]` 是命中率命门**：论坛 `undergrad_school` 写法极乱（"电子科大/UESTC/成电"同一校）。LLM 从 `SELECT DISTINCT undergrad_school` 抽全部写法归一。预计别名 3000-5000 条。
- 规模：~1200 所覆盖 99% 案例

### 维表 2 `dim_uk_university`（英国院校 + 名单公开性）— 【采集】
- 字段：`uk_uni_id PK, name_en, name_zh, qs_rank, list_is_public BOOL, list_url, list_pdf_url, banding_scheme`
- `banding_scheme` 如 `'ARWU四档'/'PriorityA-D'/'985-211-其他三档'`
- 来源：QS 排名爬取 + 各校官网公开性人工标注（见冷启动文档 3.1 逐校核实）
- 规模：Top30-50 校足够 P0

### 维表 3 `dim_uk_program_taxonomy`（英国硕士专业大类映射）— 【LLM + 人工校验】
**必须分专业大类，否则商科高线污染全校。**
- 字段：`program_raw, subject_group, prereq_tags[]`
- `subject_group` 枚举：`商科/金融 / CS&数据 / 工科 / 社科 / 传媒 / 教育 / 理科 / 法律 / 通用`
- 构建：`SELECT DISTINCT program`（英国校部分）→ LLM 批量打标 → 顾问抽检高频项
- 规模：distinct program 几百条 → 归并 ~10 大类

### 清洗主干 `stg_uk_admissions`（view，平行于 `stg_gradcafe_admissions`）
解决英联邦四个脏数据问题：
```sql
SELECT *,
  -- 坑1: gpa 百分制/4.0制混填 → 归一到百分制
  CASE WHEN gpa <= 4.5 THEN round(gpa/4.0*100,1)     -- 4.0制还原(近似,打 score_scale_inferred)
       WHEN gpa BETWEEN 40 AND 100 THEN gpa           -- 百分制
       ELSE NULL END AS avg_score_pct
  -- 坑2: decision 无 con/uncon → 从 comment 文本 LLM 解析
  -- 坑3: ielts 只有总分 → 小分留空标 ielts_sub_missing
  -- 坑4: undergrad_school 乱写 → int 层 join 别名表归一
FROM raw.liuxue_admissions
WHERE school ∈ 英联邦目标校(join dim_uk_university 别名命中)
```
> 决策：4.0 制判别用阈值 `<=4.5` 有误判风险（如 4.3/5 制），还原行打 `score_scale_inferred=true`，反推时优先原生百分制、还原样本降权。

## 二、四个功能：数据集合 + 构建方式

### 功能 1：选校定位（本科院校+均分+专业+雅思 → 冲/匹/保）

**数据集合**：`dim_cn_university`(→档位) + `dim_uk_program_taxonomy`(→大类) + **`feat_uk_entry_line`**(反推均分线) + `dim_ielts_requirement`(雅思卡线) + `entry_requirement`(官方线锚点)

**`entry_requirement`（官方线）—【直接采集】**：爬爱丁堡 PDF / UCL HTML / Sheffield 工具 / Bristol 名单 + TestDaily 种子(标 aggregator/low/待核)。字段 `uk_uni_id, subject_group, cn_tier, min_avg_score, ielts_*, source_type, source_url, confidence`。

**`feat_uk_entry_line`（不公开校均分线）—【反推】**（核心壁垒，详见三）：
- 输入：`avg_score_pct, decision, cn_tier, subject_group, uk_uni_id, year`
- 方法：**分层 + 低分位(P10-P25) + 等渗/logistic 拟合**（取 P(录取)=0.5 对应分为线，比纯分位稳）
- 输出 `feat_uk_entry_line`：`uk_uni_id, subject_group, cn_tier, line_p10, line_p25, line_iso50, sample_n, offer_n, reject_n, confidence, year_range, method`
- 样本/置信：`<5` 不出线；`8-15 有拒` 出区间+medium；`>=30` 点估计+CI+high；无拒只给下界+low
- 偏差缓解：幸存者→低分位+下界+降信；自我选择→标"或高估"；专业混淆→强制 subject_group 分层；时间漂移→近 2-3 年

**冲/匹/保规则层 `mart_uk_school_match`**：`gap=学生分-线`；`>=+2` 保 / `-2~+2` 匹 / `-5~-2` 冲 / `<-5` 不建议；雅思不达标降档标注。

**数据流**：
```
raw.liuxue_admissions → stg_uk_admissions(清洗归一)
  → int_uk_admissions_tagged (join 维表打 cn_tier+subject_group 三维标签)
  → feat_uk_entry_line (反推: uk×group×tier 算线)
官方源 → entry_requirement(爬) ┐
dim_ielts_requirement ─────────┴→ coalesce(官方优先,反推兜底)
  → mart_uk_school_match → API /position
```

### 功能 2：院校 list 分级（本科校名 → 各英国大学档位+均分线）

功能 1 的"转置视图"（功能1固定学生看所有校；功能2固定本科校看它在各校待遇）。**复用功能1反推结果，无需新增反推表。**

- list 内外判定 —【采集】：Bristol/UCL/Sheffield 公开名单 → `cn_uni_id` 是否命中 → 内(低线)/外(UCL 90 高线)
- 档位标签 — 维表给：爱丁堡 Band A-D、Sheffield ARWU 四档存进 `entry_requirement.cn_tier`（按校 banding，非全局统一）
- 不公开校：取 `feat_uk_entry_line` 对应反推线

**数据流**：`dim_cn_university(别名→tier) → {entry_requirement 官方 ∪ feat_uk_entry_line 反推} → mart_cn_school_uk_ladder → API /school-ladder`

### 功能 3：专业对口（本科专业 → 硕士专业：对口/可转/不可转+先修缺口）

英澳硬卡课程匹配，**不能靠反推为主，要规则+LLM**。

- **`dim_major_mapping` —【人工/LLM 为主】**：字段 `src_major_category, tgt_subject_group, fit_level('对口/可转/不可转'), required_prereqs[], note`。顾问+LLM 基于官方课程页建专家规则表（如"数学/统计/EE→CS 可转,需先修编程+数据结构"；"纯文科→CS 多不可转"）。~200 行核心矩阵。**这是产品知识资产,统计得不出。**
- **`feat_major_transfer_freq` —【反推,做校验】**：`undergrad_major(→src) × program(→tgt) × decision` 的**共现频率 + offer 率**。用途不是定规则,而是**校验规则表+发现盲点**（规则标"不可转"但案例大量 offer → 触发复核）。offer 率受幸存者偏差,只作信号。

**数据流**：`输入 →LLM归一→ dim_major_mapping(查 fit) ←对照→ feat_major_transfer_freq → API /major-fit`

### 功能 4：雅思规划（要求总分+小分 vs 现状 → gap）

**最干净的功能,不依赖反推**——因 `ielts` 无小分,案例侧反推不了小分线,**要求必须官方采集**。

- **`dim_ielts_requirement` —【直接采集,绝不反推】**：`uk_uni_id, subject_group, ielts_overall, ielts_listening/reading/writing/speaking, source_url, valid_until`。来源各校官网 English Language Requirements（公开权威）。Top30 × ~3 档 ≈ 几百行。
- **`feat_con_offer_ielts` —【LLM 补充】**：LLM 从 `comment` 抽 con offer 待达成雅思条件（"need IELTS 6.5 with 6.0 in writing"），部分补回案例侧小分,仅参考。

**数据流**：`dim_ielts_requirement(官方) → 逐项 gap=要求-现状 → API /ielts-gap`；`comment →LLM→ feat_con_offer_ielts(辅助)`

## 三、反推案例完整走一遍：曼大 × 双非 × CS 均分线

曼大 PG 名单不公开 → 典型"只能反推"格子。

**Step 1 filter**（经 stg 清洗后）：
```sql
SELECT avg_score_pct, decision, year, undergrad_school, program, score_scale_inferred
FROM int_uk_admissions_tagged
WHERE uk_uni_id = 'University of Manchester'
  AND subject_group = 'CS&数据'     -- 排除曼大金融高线污染
  AND cn_tier = '双非一本'           -- undergrad_school 经别名表归一
  AND year >= 2023                   -- 防时间漂移
  AND avg_score_pct IS NOT NULL
```

**Step 2 打档位标签**：`undergrad_school` 原文（"江苏大学/江大/Jiangsu Univ"）→ `aliases[]` 归一 → `tier_label`。命中失败进"未归一"暂存表人工补,**绝不默默丢弃**（丢弃加重幸存者偏差）。

**Step 3 算线**：
```python
offers  = rows[decision ∈ {Offer,Conditional}].avg_score_pct
rejects = rows[decision == Rejected].avg_score_pct
n, n_rej = len(rows), len(rejects)
if   n < 5:        line, conf = None, 'insufficient'        # 仅提示案例不足
elif n_rej == 0:   line = offers.quantile(0.10); conf='low' # 无拒→只给下界,标"或高估"
elif n < 30:       # 等渗回归拟合 P(录取),取0.5;同时给区间
                   line_iso50 = isotonic_50(rows); line=(P10,P25); conf='medium'
else:              line = offers.quantile(0.15); ci=bootstrap(); conf='high'
# 4.0还原样本(score_scale_inferred)权重0.5,优先原生百分制
```

**Step 4 样本不足层级回退**（每级降一档 confidence,标 `fallback_level`）：①放宽年份→②subject_group 升级到相邻"工科"→③cn_tier 合并"双非一本+二本"→④仍不足取 entry_requirement 种子兜底,话术降"参考线"。

**Step 5 输出**（写 `feat_uk_entry_line`）：
```
Manchester / CS&数据 / 双非一本
line_p10=80.0  line_p25=82.5  line_iso50=81.3
sample_n=11 offer_n=8 reject_n=3  confidence=medium
year_range='2023-2025'  method='isotonic+p10p25_interval'  fallback_level=0
note='论坛案例反推,非官方承诺;双非样本偏尖子,门槛或高估'
```
前端："基于 11 例历史案例估计，约 **80-83 分**（参考线，非录取承诺）"。**永不包装成官方数字。**

## 四、构建优先级与依赖 DAG

```
[第0层 地基 — 最高优先,阻塞一切反推]
  dim_cn_university (985/211/双非标签+别名归一)  ← 绝对第一前置
  dim_uk_university (英国校+名单公开性)
  dim_uk_program_taxonomy (program→subject_group) ← 阻塞专业分层
        │
[第1层 清洗主干]
  stg_uk_admissions → int_uk_admissions_tagged (打三维标签)
        │
[第2层 并行: 采集线 ‖ 反推线]
  ├─ entry_requirement     (爬官方: 爱丁堡PDF/UCL/Sheffield/Bristol+TestDaily种子)
  ├─ dim_ielts_requirement (爬官方雅思门槛) ────→ 功能4(最快上线)
  ├─ dim_major_mapping     (LLM+顾问规则) ──────→ 功能3
  └─ feat_uk_entry_line    (反推不公开校线) ← 依赖第0层全部
        │
[第3层 反推校验]
  feat_major_transfer_freq (校验 dim_major_mapping)
  feat_con_offer_ielts     (LLM 从 comment 提取)
        │
[第4层 Mart 功能聚合]
  mart_uk_school_match     → 功能1 选校定位(最愿付费,依赖最深)
  mart_cn_school_uk_ladder → 功能2 院校list分级
```

**硬约束顺序**：
1. **`dim_cn_university`(含别名归一)绝对第一**——没它 `cn_tier` 打不出,功能 1/2 反推、功能 3 专业归一全卡死
2. `dim_uk_program_taxonomy` 第二——没 subject_group 商科污染 CS 线,反推作废
3. 第 2 层四条线并行：采集线(爬官方,不依赖案例)与反推线(依赖第0层)各自推进。**功能 4(雅思)、功能 3(专业)不依赖反推,可最快上线建产品骨架**
4. 功能 1 最愿付费但依赖最深(需第0层+feat_uk_entry_line 全齐),排反推线完成后
